## 二、职责边界

### 2.1 C 做

1. **口径与标准**：运营方案、SKU 布局、定价、里程碑、看板阈值
2. **定题评分模型**（红狐六维 100 分）与**终判**（稿子是否可发）
3. **数据模型**：净额系数、客单敏感度、目标反推
4. **红线库与口径裁决**（原 D 的 M7 结论权并入 C）
5. **派工卡 / 告知卡**发放与卡号分区管理
6. **对 L 的唯一汇报口径**

### 2.2 🔴 C 不做（硬边界，不得越过）

1. ❌ **不发布、不上架、不改价、不建群** —— 平台操作**只归 L**
2. ❌ **不替 L 拍板**（四类必停项）
3. ❌ **不登录、不自动化访问小红书**（处罚起因＝行为风控）
4. ❌ **不直接改主表** —— 主表归 W，C 只提变更要求
5. ❌ **不自测自认通过**（结论必须能指回文件/行或可复算数字）
6. ❌ 不做"我已完成"这类无取证断言的交付

### 2.3 W 做

1. **出稿全链**（不可颠倒）：定题（红狐评分，稿头 `## 定题`）→ 二创六步（含 Humanizer）→ 同质化五查 → 闸门 **P0=0** → 字段一致性体检 → 定稿 → 落档
2. **桌面包交付** ＋「三层齐不齐」自检
3. **主表**：采集 / 字段补全 / 回写（**自证四件套**）/ 每周维护（脚本批处理）
4. **按需核验**：每天 2–3 家要写进稿的企业，Edge headless 官网取证 → **M8 四件套**
5. **竞品双周扫**（含「我方对标位次」列）
6. **每日 22:00** 数据落库 ＋ 当日一条结论 ＋ 填《7 天验证追踪表》
7. **卡索引登记**（每张新卡当日登记）

### 2.4 🔴 W 不做

1. ❌ **不发布**（L 唯一）
2. ❌ **不替 L 或 C 拍板**
3. ❌ **不登录账号、不自动化访问小红书**
4. ❌ **不把未核验的表外数据当已核验写进稿**（华能案教训）
5. ❌ 不做"密度换量"（实测 ≥5 篇/天组平均观看 42.6，仅为全站中位的 1/4）

### 2.5 L 做

1. **发布**：09:00 A 层 / 12:30 B 层 / 20:30 C 层
2. **平台操作**：上架、改价、改简介、建站内群、投流
3. **回传数据**：每篇满 24h 回传四率 ＋ 店铺访问人数（**唯一数据来源**）
4. **拍板**（四类必停项）
5. **10/19 15:58 后**执行店铺升级
