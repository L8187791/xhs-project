### 1 · `首评10=-` 这个符号**有两种含义**，导致「R3 是否恢复」在产出物层面不可证

**实读脚本源码**（`_sim_check.py` 第 311–315 行）：

```python
print("同质化五查：正文%.3f/标题%.3f/首评10=%s/开头12=%s/签名=%s → %s" % (
    ...,
    "★" if any(x["comment"][:10] == y["comment"][:10] and len(x["comment"][:10]) >= 8 for x, y in pairs) else "-",
    "★" if any(x["body"][:12] == y["body"][:12] and len(x["body"][:12]) >= 8 for x, y in pairs) else "-",
```

→ `-` 的**代码含义是「未命中」＝通过**；`★`＝命中＝违红线。

| 时代 | `首评10=-` 的真实含义 | 能不能引用 |
|---|---|---|
| **v1** | 两边首评**都解析成空串** → `len("")>=8` 为假 → 也输出 `-` | 🔴 **假通过**（R3 根本没跑） |
| **v2／v3** | 两边首评**取到真值但前 10 字不同** | 🟢 **真通过** |

🔴 **同一个 `-`、两种含义，输出里看不出来。** 后果：**「R3 是否已恢复」这件事，在产出物层面无法自证**。
→ **裁定**：该列改**三态**（`✅未命中`／`★命中`／`⚠️解析空`），并在结果末尾**打印「参与比对篇数 ＋ 首评非空篇数」**。**边界＝只改输出表达，阈值与判定逻辑一字不动。**
