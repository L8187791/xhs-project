# 每日竞品拆解 SOP（W 执行 · C 审核）

| 项 | 值 |
|---|---|
| 触发 | L 2026-10-16 指令：「W 侧每日 8 点加一个流程，通过红狐去做竞品拆解（按拆解步骤）并记录有价值的部分，由 C 审核是否真实有用」 |
| 执行 | **W**（每日 08:00，随 B1 早间读卡一并执行） |
| 审核 | **C**（每日 **10:00** 读卡场 → 原记 09:00，据看板 §五·补 一手取证校准） |
| 依据 | `竞品拆解框架v2_20261015.md`（A–F 六维）｜`选题定题SOP-红狐评分法-20261014.md`（红狐通道与清洗规则）｜`_协作/redfox_topic_scoring.py` |
| 产出 | **`_协作\竞品日报\YYYY-MM-DD-拆解-<竞品名>.md`**（唯一现行位；根目录 `竞品日报\` 为 10-10／10-11 的历史存档，不再写入） |
| 纪律 | 🔴 只记有价值部分；无证据写「未取到」，**不许编**（防 R1／R3 失效模式） |

---

## 一 · 拆解对象怎么选（每天 1 个，不许随机）

**配比**：求职线 4 天 比 医美线 3 天（按周计）。

**来源优先级**：

| 优先 | 来源 | 说明 |
|---|---|---|
| **1** | **有成交证据的竞品** | 例如主表竞品中已知售出 1507 件的那类账号——先拆能赚钱的，不拆涨粉不赚钱的 |
| **2** | **红狐高互动笔记所在账号** | 用 `redfox_topic_scoring.py` 跑近 30 天高互动样本，取账号 |
| **3** | **同城／同赛道对标账号** | 医美线用小红书与抖音直读实测（走 `医美线/10-实测数据` 同一口径） |
| **4** | L 或 C 临时指定的对象 | 优先于以上三条 |

**新鲜度要求**：拆解对象必须在近 30 天内有活跃更新，且拆的笔记必须是近 30 天内发布的。**禁止拆一年前的老爆款**，因为分发环境已经变了。

**去重要求**：与最近 7 天已拆对象不得重复；若必须重拆同一账号，须写明「上次拆的是哪篇、这次拆哪篇、为什么重拆」（→ 2026-10-16 补：**同账号不同层（商品页层／笔记层）视为不同拆解对象，不计入 7 天去重**；**同账号同层 30 天内不得重拆**——否则去重形同废止）。

---

## 二 · 拆解步骤（按 v2 框架 A–F 逐项，不得跳维）

对每一维，**必须写「证据 + 等级」，没有证据的维写「未取到」**。

| 维 | 内容 | 每维必答的证据要求 |
|---|---|---|
| **A 笔记风格** | 封面风格、内页结构、内容类型占比、发布频率、单篇数据、互动引导方式 | 至少给出 3 篇笔记的赞/藏/评原始数值，并注明抓取日期。**标题与正文引用必须逐字；截断须标「…」，且不得改动任何字**（→ 2026-10-16 补：引用不逐字会使 C 无法反查原始数据，P1 退化为只能采信） |
| **B SKU 布局** | 档数、价格区间、分层逻辑、原价锚定、热销标签位置、社会认同标签、紧迫感设计 | 价格与已售数须写具体数值；页面上没有写「无」 |
| **C 产品包装** | 定价设计、卖点写法、好评截图、自动发货、视觉包装、产品延伸 | 卖点写法必须**逐句摘录不超过 20 字**并注明位置 |
| **D 转化闭环** | 流量入口、信任建立、下单路径、交付体验 | 下单路径须写清步数（看到笔记 → 下单要几步） |
| **E 赛道优势** | 成本、受众、差异化、售后压力 | 成本与售后为**推断时必须标【推断】**并写成立条件 |
| **F 笔记内容结构** | 具体结构、结构好处、可复用点 | 结构须能用一句话概括（开头怎样／中间怎样／结尾怎样） |

---

## 三 · 「有价值部分」的写法（本 SOP 的核心约束）

🔴 **篇幅上限 800 字**。这个上限是刻意的：它逼你只留真正有价值的部分。**写满一页不等于拆得好。**　🔴 **字数口径（2026-10-16 固定）**：一律按**全文汉字**计，命令 `len(re.findall(r'[\u4e00-\u9fff]', 全文))`；**报「完成」前必须回数一次并把命令原始输出贴进回执**（C／W 曾各算各的致争议）。

每篇日报固定包含两节：

```
## 可复用点（最多 3 条）
1. 【动作】<能直接做什么> ｜【落点】<落到哪篇稿／哪个交付物> ｜【依据】<哪条证据>
2. …
## 不可复用 / 风险
1. <哪些不能抄，为什么>
```

**可复用点的判定标准**：必须能在**本周**落到具体的稿或交付物上。凡是「以后可以借鉴」「值得学习」这种无法落地的话，**一律不算可复用点**，写进去等于没写。

## 四 · 红狐数据使用规则（沿用既有 SOP，不得自作主张）

1. 用 `_协作/redfox_topic_scoring.py`（venv 解释器）拉数据，产出 `_redfox_topic_score.json`。
2. 清洗三大陷阱：「26 届」剔除中考高考样本、「大厂」剔除职段子、量级字段统一转数字。
3. 样本 n 小于 5 的方向不得单独下结论，只能标「样本不足」作参考。
4. **我方后台实测（A 级）优先于红狐评分（B 级）**。红狐用于没有我方数据的空白处，不得用来推翻已有实测。
5. 🔴 **红狐数据仅供内部使用，不得出现在任何对外交付物中**。

---

## 五 · C 的审核标准（五条通过线，逐条给结论）

C 在每日 09:00 读卡场完成审核，结论分三档：🟢 采纳 / 🟡 部分采纳 / 🔴 退回。

| # | 通过线 | 判定方式 |
|---|---|---|
| **P1** | **证据可核** | C **随机抽 1 条结论实跑复核**（打开笔记、跑脚本或读截图），核对不上即不通过。**C 不得只读文字判断** |
| **P2** | **新鲜度达标** | 对象与笔记均在近 30 天内活跃 |
| **P3** | **非重复** | 与最近 7 天拆解不重复，且看板在办清单里没有同类结论 |
| **P4** | **可执行** | 可复用点至少 1 条写明落点（哪篇稿／哪个交付物），且本周可落地 |
| **P5** | **无编造** | 无「未取到」被写成结论；所有【推断】均已标注并写明成立条件 |

**审核结论的处理**：
- 🟢 → 采纳项写入推进看板「可复用点」区，并派生一条落地卡（派给 W 或进定题）。
- 🟡 → 列出可用的 1 至 2 条，其余退回理由写清。
- 🔴 → 写明退回原因；**次日重拆**。
- 🔴 **连续 3 次退回即触发框架复盘**：这说明问题在拆解框架或对象选择，而不在 W 的执行力。届时由 C 修订本 SOP，而不是继续要求 W 更努力。

## 六 · 检验「是否真实有用」的两个指标

| 指标 | 定义 | 目标 |
|---|---|---|
| **采纳率** | 当周（🟢＋🟡）篇数 ÷ 总篇数 | ≥ 60% |
| **落地率** | 已采纳且**实际进入稿件或交付物**的条目数 ÷ 已采纳条目数 | ≥ 50% |

这两个指标写在推进看板「指标」区，由 C 在每周一评估时更新。**如果采纳率低，改框架；如果采纳率高但落地率低，说明拆解与执行脱节，改流程。**

---

## 七 · 红线（拆解的边界）

1. **可学结构，不可搬文案**。竞品文案原样复制进我方稿件即为违规。
2. **不得采集竞品的用户信息**（评论区的用户昵称、联系方式等一律不记录）。
3. **医美线拆解不得复制任何医疗宣传素材**（效果图、术前术后、患者形象），只拆结构与流程。
4. **不得用拆解结果对外披露来源**（不能写「某竞品卖 1507 件」这类带具体身份的外部话术）。
5. 拆解不产生任何对外动作，不评论、不点赞、不关注竞品。

---

## 八 · 本 SOP 最可能失效的地方（自曝）

第一，**每日一篇的节奏可能产出「为交差而拆」的内容**，这是本 SOP 最大的风险，而篇幅上限与「必须写落点」这两条就是为它设计的。

第二，**C 的审核也可能变成橡皮图章**。因此 P1 明确要求 C 实跑抽查，且抽查对象必须是随机的，不能只挑最容易核的那条。

第三，**红狐的数据通道若当日不可用**，当日改为人工直读小红书页面并注明「降级通道」，不得凭记忆填写。
