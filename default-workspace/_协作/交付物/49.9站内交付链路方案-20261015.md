## 一 · 问题定义（为什么必须专门设计）

| 事实 | 后果 |
|---|---|
| ① Skill 是**本地程序**（需下载安装/命令行运行） | 无法作为小红书商品卡的"虚拟商品"直接发货（站内发货＝文件/提取码） |
| ② 小红书**禁止站外引流、诱导私信**（P0 零容忍） | 一旦"引导加微信/发网盘链接"→ 账号级风险 |
| ③ 我们的号是**作品集/信任凭证**，且处罚期刚过 | 任何越界动作代价放大 |
| ④ 但 Skill 是唯一差异化抓手（纯表格赛道同质化极重） | 不能不用，只能**换个交付位置** |

→ **结论：Skill 不进商品卡主体，只做"站内闭环的售后附赠"。**（该结论**未变**；§六.1 前置已由 L 实测闭合）

## 三 · 站内链路设计（三条路径，推荐 B）

### 路径 A · 纯数据版（零 Skill）
- 交付：仅 #1–#3 + #6（说明写"这份表怎么用"）
- **不交付任何本地工具**
- 优点：**零风险**、零安装门槛
- 缺点：放弃差异化
- 适用：链路未打通时的**兜底**（**本轮已确认不需启用**，见 §六.1）

### 路径 B · 站内群交付（🟢 推荐 · 2026-10-15 L 实测闭合）
```
买家付款
  → 站内订单发货：CSV + 使用说明（不含任何站外链接）
  → 引导进「站内群聊」（小红书群聊，无粉丝门槛）
  → 群内提供：月更快照 + 周一截止周报 + Skill 安装包与使用录屏
  → 售后答疑全在群内 / 订单留言
```
- **关键约束**：
  1. 全部动作在**小红书站内**（订单、群聊）完成，**不出现任何站外链接/微信号/网盘**；
  2. Skill 安装包以"群文件/说明"形式提供，说明写**用法**，不写"加我私发"；
  3. 群公告固定一句：「所有资料和更新都在群里/订单里，不用私信我要链接」——**反向封堵私信诱导**。
- 优点：站内闭环、S 级合规、群还能沉淀复购
- 缺点：需建群并维护

### 路径 C · 站内"操作演示"化（Skill 转内容）
- 把 2 个 Skill 的**能力做成站内可消费内容**：图文/短视频演示"怎么用这份表排出投递顺序"
- 买家拿到的 Skill 等同于路径 B，但对外**只宣传"能力"不宣传"软件"**
- 优点：降低"装软件"心理门槛，内容还能反哺笔记素材
- 缺点：制作成本

> **推荐组合：B 为主 + C 为宣传话术**——交付走 B（群），对外宣传走 C（讲能力不讲安装）。

## 四 · 三条硬铁律（写进交付 SOP）

1. 🔴 **不引导私信**：任何物料**不得**出现"私信我""评论区扣1""加我发你"——与项目既有纪律一致。
2. 🔴 **不出现站外标识**：不出现微信号/QQ/网盘链接/外部网址（Skill 内若含官网链接，说明文档中不复制）。
3. 🔴 **不承诺"自动发货"**：措辞用「按页面提示获取」，与 Z3-2 一致。
