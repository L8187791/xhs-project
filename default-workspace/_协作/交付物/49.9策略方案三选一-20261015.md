## 二、三个方案

### 方案 A · 资料打包型「一次买断·资料全给」

> 一句话：**49.9 = 我们的表 + 一堆周边资料**（靠"东西多"撑客单）

| 项 | 内容 |
|---|---|
| **交付物** | ① 200 家全量 CSV（含可信度分级+核验来源+日期）② 简历模板包（应届/往届两版）③ 网申避坑清单（④填表自查器）④ 投递排程表（①排程器静态版） |
| **Skill** | ①排程器 + ④填表自查器（售后附赠） |
| **时效** | 单批快照（不含更新） |
| **对标** | ④朱迪 58.88 档（全部+300 套题库，4.8 万件）｜⑤Suuny 25.99（打包题库面经） |
| **红狐支撑** | 付费意愿 n=64 中位 5000 → 中客单有需求；打包＝通用提客单动作（B 级） |
| **定价结构** | 原价 79.9 → 实付 49.9（6 折）｜热销标置本档 |

**✅ 优势**
- 交付即完成，**无持续维护成本**（不含更新）——绕开"回写四件套跑顺一周"的硬前提 🔴 → **可提前上架**
- 客单感知值最高（"买一送四"），对首次购买者心理阻力最小
- 素材现成（CSV 已交付、④自查器清单静态）

**❌ 风险**
- 🔴 **版权 P0 风险**：简历模板/面经若来自第三方＝版权侵权（P0 零容忍）→ 必须**全部自产**
- 🔴 **与"可核验"定位弱相关**：打包资料再多，也不强化"每条标来源"的差异化内核
- 无复购、无升级路径（买断即终止）
- 赛道最同质（④⑤⑥全在做），无护城河

### 方案 B · 时效订阅型「买更新·长期跟踪」

> 一句话：**49.9 = 数据 + 长期更新**（靠"时间"撑客单）

| 项 | 内容 |
|---|---|
| **交付物** | ① 200 家全量 CSV（含往届可投字段）② **月更快照**（每月一版，至 2027-04-30）③ **周一截止周报**（每周推当周硬截止） |
| **Skill** | ①排程器 + ⑤冷门机会雷达（双 Skill，WB164 已定稿） |
| **时效** | 月更至 **2027-04-30** |
| **对标** | ⑦MinNan 90/180/360 天分档（"无 offer 延至入职"）｜④朱迪 98.88＝日更到 28 年 7 月｜⑪校招推推 66 元＝每日更新 |
| **红狐支撑** | **99.9-A 跨周期组中位 2035**（vs 单批数据）；付费意愿组 top 全是"持续有用"型内容 |
| **定价结构** | 原价 99.9 → 实付 49.9（5 折，对标⑦MinNan 原价 79.9）｜热销标置本档 |

**✅ 优势**
- **最贴合红狐"数据型"结论**：竞品高价档的共同点就是"长期更新"（④日更到 28 年/⑪每日更新/⑦360 天）
- 天然"可核验"延展——每版快照都带 version/updated/changelog，与我们的差异化内核**同源**（同一套自证四件套）
- 有复购与升级路径（→99.9 延长至 2027-07）
- WB164 已定稿，**执行方案现成**

**❌ 风险**
- 🔴 **维护成本最高**，且硬前提②（回写跑顺一周）**未满足** → 必然顺延（10/22–24）
- 🔴 **断更＝差评**（案例⑧反面：断更→评分 4.2）→ 承诺月更即背上持续交付义务
- 若只做月更而客户预期"日更"（对标⑪每日更新）→ 预期管理风险
- 交付周期长 → 首个差评窗口长

### 方案 C · 人群垂直型「往届生专版」

> 一句话：**49.9 = 只服务往届生**（靠"人群准"撑客单）

| 项 | 内容 |
|---|---|
| **交付物** | ① **往届生专版 CSV**（"是否招往届"字段为核心，22/1/177）② 往届可投类型速查（只给类型不给名单，合规）③ 月度更新（往届机会补录） |
| **Skill** | ②往届生可投判定器 + ⑤机会雷达 |
| **时效** | 月更至 2027-04（专注往届/补录窗口） |
| **对标** | ⑦MinNan（主打"往届生专属"3.2 万粉/84.4 万赞）｜⑩Cici（往届机会，1491 粉→1103 件）｜⑨牛马学姐「往届版」矩阵号 2.7 万粉 |
| **红狐支撑** | 🔴 **最强**——99.9-B 跨人群（往届+社招）中位 **10000**、头部 17 万、89% 破 3000，为全组最高 |
| **定价结构** | 原价 89.9 → 实付 49.9（5.5 折）｜热销标置本档 |

**✅ 优势**
- **红狐数据最高热人群**（中位 10000，是工具型 1428 的 7 倍）
- **与 19.9 形成互补而非重合**——19.9 切应届、49.9 切往届，两条线不打架
- **可核验内核最自然**：往届生最痛的是"我还能不能投"，我们给的是**逐家带核验来源的"是否招往届"事实**（不是二手"往届友好"门槛断言）
- 三个竞品案例共同验证该人群存在（⑦⑨⑩）

**❌ 风险**
- 🔴 **字段覆盖弱**：往届字段现状 22 家"是"/1 家"否"/177 家空 → **可用数据太少**（原 29.9 放行条件「≥15 家 A/B 级往届生」虽随 29.9 取消而作废，但**数据短板仍在**）
- 🔴 **合规紧**：②往届判定器合规分仅 6/10（最高优先原则下"宁可少写不可保留"）→ 只能给类型不给名单，交付感知值可能低于预期
- 往届生市场规模小于应届（⑩Cici 单篇仅 1 赞、搜索流量型天花板低）
- 需新增"往届生"内容线（当前内容库偏应届）

## 四、W 的倾向（推断，非结论）

**推荐序：B ≻ C ≻ A**，理由：
1. **B 与店铺定位最同源**——"月更快照+自证四件套"就是我们已有的交付机制，不用新建能力；且对标案例最成功（④/⑦/⑪ 全部靠更新撑高价）。
2. **C 数据最强但地基最弱**——红狐中位 10000 支持切往届人群，但往届字段只有 22 家可用，硬推＝交付空壳。建议**先把往届字段补到 ≥40 家**再启用。
3. **A 最易上架但最无护城河**——且版权风险与"可核验"定位不搭。

**若只能选一个 → B；若能等 → B 打底 + C 做第二张（往届专版）**，即"通用订阅 + 人群垂直"双产品矩阵（对标 ⑨牛马学姐矩阵号打法）。
