# 06 · 双店运营制度（v1 · 2026-10-12）

## 〇、核心原则

> A 店北极星（30 天 19.9 卖 30 单）+ 接棒节点 > B 店一切动作。B 店是 A 店的**加法**，任何让 A 店接棒减速的 B 店动作 = 直接违规动作。

## 一、六项隔离制度

| # | 隔离项 | 机制 |
|---|---|---|
| 1 | **优先级恒定** | B 店所有动作（挂链/改价/换赛道）执行前先过检查项：A 店日更是否断更 / 北极星进度是否停滞 / 99 包与 RedSkill 节点是否被推迟——任一命中即 B 店动作延后 |
| 2 | **产能硬约束** | A 店日更 2 篇固定不变；B 店日更 ≤2 篇且**仅当总产能 >4 篇时执行**；产能不足 → B 店自动降频（每周 3 篇），绝不动 A 店节奏 |
| 3 | **数据/资产隔离** | 两店数据文件、核验台账、排版母版物理隔离；核验工具链可共用（效率），数据文件不共享；B 店不得引用 A 店 131 家库 |
| 4 | **复盘隔离** | 22:00 日复盘以 A 店为主；B 店进周复盘（每周 1 次），不进日复盘，避免稀释决策带宽 |
| 5 | **失败隔离** | B 店独立承担启动成本；4 周 0 单 → 换赛道或弃号，不得占用 A 店资源回血 |
| 6 | **口径隔离** | B 店不触碰 A 店既定口径（PAUSE_SALES / 131 / 09:00+17:30 排期 / 标签体系），两套口径各自维护 |

## 二、设备与登录制度（关联防控）

- 电脑 A ↔ A 店、电脑 B/独立浏览器容器 ↔ B 店、手机各挂一个、不混登。
- 同 WiFi 下 3~5 个账号一般没问题；同 WiFi + 同模板批量发是禁区。
- 登录隔离：不同浏览器（无痕模式）分别登录、固定浏览器不窜；同一 WiFi 短时间不同账号发相同模板内容会被判同质化。

## 三、出图隔离（技术制度）

- `note` 加 `account` 字段优先、缺省回落全局（方案 A）。
- **三处同改**：4 个版式函数 `header(d)` 透传 spec 字段 + `render()` 从 note 层取店名 + 表格封面脚本显式写死店名与全局解耦——只加字段不改透传 = 假修复。
- 改前备份到 `_备份/`；改后自测 5 项（A 店页眉不变 / account 注入生效 / 不带 account 回落默认 / 三图零差异 / 全量重跑比对）。
- **禁止直接改全局 `_account_name.txt`**（会静默污染另一店全部出图）。

## 四、版本与同步制度

- 版本同步链路：`_rebuild_from_json.py`（正向 json→xlsx/md/txt）→ `_pack_skill.py`（打 zip）→ `_build_199.py`（重建 19.9 交付件）。
- **禁用反向脚本**（读旧 xlsx 写 json）——会把 131 家打回旧版。
- 编辑主文档前先 Read 再 Edit（防并发修改）；改前备份。

## 五、复盘制度

- 22:00 日复盘（A 店主）：数据简报只读不改动作，复盘才决策。
- 周复盘（B 店 + 接棒节点）：每周 1 次。
- 数据取数：内容数据看创作者中心；商品/订单数据看千帆；个人售卖数据看手机 App「专业号」后台（用户回传）。
