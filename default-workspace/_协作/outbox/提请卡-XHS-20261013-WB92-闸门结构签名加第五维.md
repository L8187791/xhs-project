## 一、为什么提这个（承接 WB91）

## 三、具体改法（**1 行**，未执行）

`compliance_gate.py` L294–300，只删掉第一维的 `min(..., 4)` 封顶：

```python
# 现状
return (min(len(paras) // 3, 4), has_num, has_bullet, ends_q)
# 改为
return (len(paras) // 3, has_num, has_bullet, ends_q)
```

回归验证方式（改后必跑）：
1. `python compliance_gate.py 干货批次01_第1至4篇\成稿_批次01_第1至4篇.md 干货批次02_03_第5至10篇\成稿_批次02_03_第5至10篇.md` → 预期 **P0=0 P1=0**
2. 新四篇定向跑 → 预期 **P0=0 P1=0 成稿 4 篇**（不变）
3. 历史+新混合跑 → 预期 **P1=0**

## 四、双面验证

### ✅ 支持层

1. **A 级（实测）**：方案 B 让现存 **3 处 P1 全部归零**，且新四篇最大聚集 **1 篇**（三个方案里最安全）。
2. **A 级（实测）**：`min(len(paras)//3, 4)` 封顶把 12/14/16/25 段全归为一档——**这个缺陷客观存在**，不是我的推断。01（12 段）与 05（16 段）差 33% 却同档，已实证。
3. **A 级**：成本极低——**1 行改动**，且是**增量**（保留原 4 维，只放开一个封顶），不是推翻判定逻辑。
4. **B 级**：与 WB91 的 A 级结论（三篇正文 Jaccard 0.002–0.003，文字零雷同）方向一致——更细的尺子得出更接近真实的结论。

### ❌ 反对 / 风险层

1. 🔴 **灵敏度下降（最主要风险）**：段数每 3 段一档后，**差 1–2 段的"近模板"会被分到不同档而漏报**。即 B 方案**降低误报、提高漏报**。若平台真按"批量模板"抓，这个改动会让闸门更迟钝。
2. 🔴 **不能反向断言"现有 P1 是误报"**：Jaccard 低只证明**文字**不雷同，**不证明结构不该管**。结构聚集管的本来就是"批量模板特征"，与文字雷同是两个独立维度。WB91 里我用 Jaccard 作为"可不改"的依据——**这条只能用来说明"不必急着改稿"，不能用来说明"指标是错的"**。
3. 🔴 **只修了第一维，没修更粗的两个布尔量**：`has_num` / `has_bullet` 只问"有没有"、不问"多少"（比如 1 个编号 vs 7 个编号都算 True）。方案 B 未触及这一层。
4. **C 级（仅提示）**：闸门是三方共用的判定基准，改它会同时改变豆包复核时看到的结论——需三方口径同步，否则出现"WB 这边 0 个 P1、豆包那边 3 个 P1"的对不上账。

### 我的倾向（**推断，非事实**）

**倾向方案 B**，但**附一条必须同时做的补偿**：把"结构聚集"的判定篇数阈值从 **≥3 篇**下调为 **≥3 篇不变、但增加一条兜底**——即：**若两篇签名相同且正文 Jaccard ≥0.15（低于现行 0.28 但明显非零），也报 P1**。这样"漏报"风险被部分对冲。
🔴 但这条兜底属于**新增规则**，同样要拍板，我不自行加。
