## 三 · 五处优化点（按 ROI 排序）

### 🔴 优化点 1 · 闸门执行权与「自测自认通过」红线冲突

| 项 | 内容 |
|---|---|
| **现状** | `compliance_gate.py` 由 **WB 跑**；豆包做「复核」 |
| **冲突条款** | `职责表 v4` §四第 3 条：「**不自测自认通过**——凡我产出的数字/结论，必须可由用户或豆包独立复算」；`主文档 §12` 同款表述 |
| **实证风险** | 2026-10-12 晨，我实测发现该闸门存在「**假通行证**」坑：`parse_notes` 只认固定格式（`## 第X篇 / **标题** / **正文** / **标签** / **置顶首评**`），对普通稿文件跑会输出「**成稿 0 篇 · P0=0 P1=0 ✅**」——**全绿但什么都没扫**；路径写错亦输出同款 |
| **结构性缺陷** | 闸门**我写的、我跑的、我判的**；豆包核的是**我的输出**，非原始文件 → 二审原料被一手污染 |
| **提请方案 A（推荐）** | 闸门**保留 WB 跑**，但 WB 交付卡**必须附完整 stdout 原文 + 「成稿 N 篇」明示**；**豆包独立复跑一次**并回报「我跑到成稿 N 篇」 |
| **提请方案 B** | 闸门改由**豆包跑**，WB 只交稿（代价：豆包需本地代码执行环境） |
| **建议硬规则** | 落为一条：「**闸门输出中「成稿 N 篇」必须等于实际可发篇数**；若 N=0 而实际有稿 = **空跑，判未通过**，不得记 ✅」 |
| **严重度** | 🔴（已有实证坑，非理论风险） |

### 🔴 优化点 2 · 卡索引缺「当前最大号」计数器（防未来不同步）

| 项 | 内容 |
|---|---|
| **现状** | 分区制已存在（WB/DB/DS 独立递增，卡 86 起启用）；**机制本身正确** |
| **残余风险** | 因两边**各自递增**，若一方离线/漏登记，可能出现在**同一天内**补发旧序号 → 与已发卡撞号。当前 `卡索引.md` **无「当前最大号」可视区**，发卡前需自行扫描全表才知道下一号 |
| **实测数据** | 当前最大号：**WB52 / DB22**（WB52 起审、WB53 为本卡） |
| **提请方案** | 在 `卡索引.md` **顶部加一个「当前最大号」计数区**（WB__ / DB__ 两行，发卡时先读再递增）；**不改历史编号**（遵 R1） |
| **严重度** | 🔴（低成本、防的是"同号两卡"这类不可逆混乱） |

### 🟡 优化点 3 · 豆包裁定卡的数字结论缺「可复算性」

| 项 | 内容 |
|---|---|
| **现状** | WB 出卡**必附**实测字节数/路径/复算过程（如 WB50/WB51）；豆包裁定卡多为**结论式**（「复核成立」「放行」「接受」） |
| **结构性缺陷** | 豆包是**最终审核方**，其结论**无下游可抓** → 审核本身未被审核，链未闭环 |
| **正向对照** | 豆包 WB51 裁定卡已做对一次：「WB 用 3198/12661 实算点击率，复算正确，接受」—— **本卡正是提请把这次的做法固化为规则** |
| **提请方案** | 豆包裁定卡**凡涉数字者，必须附「我复算的过程」**（算式或原始截图），不得只给结论。例：「我用 3198÷12661 = 25.26% 复算，与 WB 一致」 |
| **严重度** | 🟡（防的是终审环节无回溯，非当前已出错） |

### 🟡 优化点 4 · 用户角色表述被低估

| 项 | 内容 |
|---|---|
| **现状** | `职责表 v4` §一 + `主文档 §12`：用户 = 「**拍板 + 平台操作**」 |
| **实测事实** | 用户实际承担 **4 个角色**：① **唯一信息源**（「B 店独立登录环境已具备」——只有现场能判断）② **唯一拍板人**（PAUSE_SALES / A层8标签 / 09:00发布 / 家数131）③ **唯一平台操作者**（发布/上架/截图回传）④ **边界守卫**（2026-10-12 我探测浏览器登录态时，**用户中断并直接给结论** → 我停止探测） |
| **提请方案** | 用户角色改写为：「**唯一信息源 + 唯一拍板人 + 唯一平台操作者 + 边界守卫**」 |
| **为什么重要** | 现表述把用户置于"执行末端"，易诱发 AI「先办了再报」的冲动；实际用户是链条的**起点（提供事实）与终点（扣扳机）** |
| **严重度** | 🟡（表述层，但影响行为） |

### 🟡 优化点 5 · 缺「卡住升格」机制（防僵尸卡）

| 项 | 内容 |
|---|---|
| **现状** | 卡片一旦阻塞即**无限期停在「待数据/等用户」**，无责任方、无时限 |
| **实证** | ① **A01**：2026-10-12 06:08 因「2027 国考公告未发布」卡住 → 至今无解除时点（公告何时出？没人盯）② **关键词矩阵**：卡在「等用户 App 截图」→ 无时限 |
