# 发文检查器（标题打分 + 人设 + 时段）

## 位置
`D:\Documents\deepseek-harness\default-workspace\发文检查器.py`（依赖同目录 `标题打分器.py`）

## 用法
```bash
python 发文检查器.py                      # 跑内置的明日候选
python 发文检查器.py "标题1" "标题2" ...   # 给指定标题打分
```

## 查三件事
1. **人设一致性**：人设 = 「踩过坑的过来人」。❌ 自称学姐/学长/老师/专家/HR/面试官；❌ 教你/带你/保证/保姆级；⚠️ 必须/一定要。
   （「面试官问你…」里的面试官是叙述对象，不判违规 —— 只有自称才违规，守则 42）
2. **时间节点建议**：A 层信息型 14:00–16:00 首选、17:30–18:30 次选；B 层方法论 17:30–18:30 首选。样本仅 7 篇，**别过度解读**（守则 41）。
3. **标题打分**：综合分 = **标题分 × 0.6 + 人设分 × 0.4**（守则 44）。

## 硬约束
- **标题 ≤20 字**（守则 62）：超过根本发不出去。打分器在前 20 字内仍可给 90+（如「本周12家秋招网申截止汇总」13 字 = 97 分）。
- **打分器的正确用法**（守则 40）：用来**避免发低分标题**，不是打到 90 就爆。爆款归因里曝光贡献 49 倍、标题只贡献 2.5 倍 —— 标题是引信，平台推荐是炸药（守则 36）。

## 验收
- 成稿标题**先数字数**再打分；>20 字直接回改。
- 出稿候选制：A 层 3 个候选（选 1–2）、B 层 3 个候选（选 1），每条附综合分 + 缺什么 + 建议时段（守则 43）。
- **同层同日只发 1 条**（防同构）。

## 边界
- 本工具只给分与提示，**不替代合规闸门**：发稿前仍需过 `compliance-gate`。
- 不生成内容成稿（归主运营）。
