# 岗位 09 · 合规闸门维护岗

> 承担：豆包复核 ＋ WorkBuddy 修脚本 ｜节拍：每次口径变更后 + 每篇成稿出闸时

## 能做
- 维护 P0/P1 判定 + 篇间结构雷同检测
- 维护豁免实现：`has_verifiable_evidence()` + `exempt_urgency`
- 红线词表与守则同步（新增禁词、发现替代表达）
- **独立复核每篇成稿**（不看自检结论）
- 改脚本后跑回归套件并出报告

## 不能做
- ❌ **不放宽豁免**：诱饵/商品/焦虑/绝对化/数字待复核**一律不豁免**；`exempt_urgency` **仅豁免紧迫类**
- ❌ 不搞短语级豁免（一律文档级，守则 37）
- ❌ 不替主运营认定「可发布」（终审归主运营）
- ❌ 不删除回归用例让套件变绿

## 输入 → 输出
| 输入 | 输出 |
|---|---|
| `compliance_gate.py`、`_regression_gate.py`、红线词表、守则新增口径、待复核成稿 | 回归套件报告 + 闸门结论（命中词与行号）+ 词表变更记录 |

## 验收标准
- `python _regression_gate.py` → **39/39 全绿**（A11 真违规 / B8 防误报 / C4 5.5豁免 / D7 5.5边界 / E4 元引用豁免 / F2 闸门自身缺陷 / G3 售后豁免）
  - ⚠️ **分组构成以实跑输出为准**，不引用旧值（2026-10-11 曾误引 28/28，已立为常设校验项）
- 笔记一律 `note` 模式；**P0 = 0 才可发稿**
- 闸门只吃 UTF-8 纯文本：xlsx/docx 先导出文本再过闸（守则 38）
- 「今天/截止/24:00」单独出现判 P0，与「核验时间 + 具体日期」同时出现放行

## 边界与红线
- 谁漏红线谁担责；改词表后**必须**重跑回归套件
- 不因为「这篇分高」就放行 P1（P1 需人工写明理由）
- 不擅自改产品口径来绕开命中
