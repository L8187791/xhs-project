# 岗位 10 · 数据治理 / 归档岗

> 承担：WorkBuddy ｜节拍：每次收/发卡后 + 每周日

## 能做
- 维护两轴：`source_level`（A/B/C + ⚪确认滚动）与 `date_form`（hard/rolling/to_verify/none）
- 补 `source_url`（**现状可追溯率仅 16%**：110/131 条无链接，守则 26）—— 逐批补
- 跑 `小红书项目_归档同步.py`（增量同步，守则 30）
- 出缺口清单：哪几条缺 source_url / 缺 date_form / 两轴空值

## 不能做
- ❌ **不包装来源等级**：没真核过官网就不许标「官网原文」
- ❌ 不把补充池混入主表（111 家主表 vs 11 家补充池，如实说明区别，守则 18）
- ❌ 不改产品口径 / 家数 / 版本号
- ❌ 不删除源文件；同步只做单向增量

## 输入 → 输出
| 输入 | 输出 |
|---|---|
| 时间表 xlsx（131+11=142 家）、三方产生的新文件、归档同步脚本 | 同步记录（`D:\小红书项目\00_归档同步记录.md`）+ 两轴缺口清单 |

## 验收标准
- 两轴无空值
- **`to_verify` 判据正确**（守则 39）：前提是**先存在疑似截止日**；根本没有可核日期 → `none`（发布日、宣讲日都不算）
- **「官方入口」判据 = 点进去能不能直接投**，不是域名归谁（守则 22）；排除公告转载页（offcn.com 等）
- 二级单位一律写「集团名·单位名」（守则 23）
- 归档后核对同步记录的**时间戳与新增条数**，不看「文件存在」就算过（守则 2.4）
- ⚠️ 根目录未映射的 md 只告警不复制 → 需手动归入对应分类目录

## 边界与红线
- 数据宁缺毋假：不补不实的链接与来源
- 不改时间表里的截止日数值（那是岗位 03 核验的事）
- 归档不删目标侧文件
