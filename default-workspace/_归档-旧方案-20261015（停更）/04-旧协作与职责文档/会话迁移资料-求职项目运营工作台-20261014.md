## 
  7. 踩坑清单（12 条 · 高价值，直接省返工）

  **SDK 调用必须用字面量 databaseId 或名为 `DATABASE_ID` 的常量**（DSDK002）。自定义名如 `TODO_DB` 不被识别。多表场景：每个 `db.xxx()` 内联字面量，或每表一个带字面量的薄封装。

  **别用 innerHTML 拼 HTML 字符串**（尤其含 ``）：同时触发 PQ001（正则剥离器把 `` 误判为正则起始 → 括号判定失衡）+ PQ005（XSS）。**正解：`createElement` + `textContent` 构树**。

  **`['catch'](...)` 不被 PQ003 认可**，必须写标准 `.catch(...)`（ES5 合法）。

  `lint_database_sdk_usage.py` 用 `--schema` / `--schema-file`；`lint_schema.py` 只认 `--schema` / `--stdin`（无 `--schema-file`）。

  `lint_schema.py` 若 schema 带 `sdk_calls_found: true`，**必须同时给 `existing_databases` 数组**。

## 
  10. 工作方式铁律（用户已固化，接手方必须遵守）

  **事实状态铁律**：用户用假设/征询语气提问时（「如果有人下单…」「这样行吗」），**先确认事实状态再动手**，不得按既成事实推进并写进档案。里程碑级事件（破首单/达成节点）必须先问一句「这是已经发生了吗」。

  **输出事实纪律**：每次回答收尾显式分栏——**① 可验证事实**（每条附证据来源）／**② 个人判断与推测**（标注为推断）。查不到的内容直接删，不写进回答也不写进档案。状态类断言（已发布/已上线）先取证，取不到就写「无法查证 + 待你确认」。

  **提案双面验证铁律**：用户提出任何想法/说辞/方案时，回答**必须同时给出 ✅ 支持层面 与 ❌ 反对层面（或风险层面）**，两侧都要真去找依据并标证据等级（S 平台实测 / A 真实帖子数据 / B 跨平台印证 / C 推理），最后一栏给倾向判断并标为推断。**禁止**只顺着说、只挑刺、或两栏都是空话。

  **改口依据铁律**：任何改口（标签/词根/标题/时间/定价/选题）必须给依据并标等级；**C 级推理不得推翻 S/A 级定案**；有依据地「不改」也要说明依据。

  **协作方式铁律**：凡需用户拍板/确认/选择/决定的事项（含「要不要…」「是否…」），**一律用「提问 + 2–4 个选项」交付**，不得写编号文字清单。**自查范围必须含收尾段**——回执/交付卡/总结段最易漏。

  **修订前先备份**，按版本号迭代；**数据不可得走降级路径**——不编造，输出「待验证 + 用户操作清单」。

  **回磁盘实跑复核**，不采信单方报告；AI 严格执行不越界决策（**AI executes; user pulls trigger**），未拍板事项不自行写入主文档。

  输出偏好：表格对比 + ✅🔴🟡 分层 + 一句话状态总结 + 下一步选项。

  **隔离纪律**：本资产属「求职 A 店」，与 B 店「考公选岗资料」、手帐项目严格零交叉（`_协作` vs `_手帐`）。
