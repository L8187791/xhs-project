## 一 · 方案 1：秋招网申倒计时·投递优先级排程器 ⭐主推

**适配逻辑**：我们卖的就是「131 家网申截止时间表」，Skill 与产品是**同一份数据的两种交付形态**——Skill 给方法论与判断，产品给完整数据。天然不冲突、不自我替代。

### 1.1 适用赛道与产品
- 赛道：校招/秋招求职资料
- 绑定产品：A 店主推 **¥19.9「2026 秋招网申截止时间表（131 家）」**
- 适配逻辑：产品是"数据"，Skill 是"用这份数据的判断方法"。免费体验到的是方法，付费买的是省掉找数据的时间。

### 1.2 目标人群与核心痛点
- **人群**：26/27 届应届生，尤其**双非、信息渠道少、一边实习/考研一边投**的人
- **场景**：晚上打开十几个招聘公众号，看到一堆"XX 网申即将截止"，**不知道今天该先投哪家、哪家快关了、哪家自己够得着**
- **未被满足的需求**：
  1. 现有信息是**按发布时间排列**的，不是按"你的剩余时间"排列
  2. 没人告诉你**优先级**——先投快关的还是先投匹配度高的，是个真实决策困境
  3. 截止日散落在几十个公众号里，**没有一处能一次看全**

### 1.3 Skill 核心能力
| 用户输入 | Skill 输出 | 解决的决策问题 |
|---|---|---|
| 毕业年份 / 学历 / 专业方向 / 目标行业 / 目标城市 / 已投过的企业（选填） | ①**今天/本周必投 Top3**（按"剩余天数 × 你的匹配度"排序，附理由）②**三类清单**：快关的（≤3天）/ 可从容准备的（≥10天）/ 你条件够不上的（直接劝退，省时间）③**一个反直觉提醒**：如"你标的最想去的 XX 还剩 12 天，但它的笔面流程比别家长 2 周，现在不投就来不及" | ①今天先投哪几家 ②哪家该放弃 ③什么时候投不算晚 |

**关键设计**：输出末尾**故意留一个真实缺口**——"以上基于你填的 6 项；**完整 131 家含行业/城市/学历门槛/剩余天数，可按条件筛**，这部分我整理了现成的表。"

### 1.4 与产品的捆绑方式（转化路径）
```
刷到笔记（标题带截止紧迫感）→ 点末尾 Skill 组件 → 详情页看到示例输出（被戳中："我确实不知道先投哪家"）
  → 复制口令（少数人真跑，跑完更痛）
  → 回笔记正文看到"完整 131 家表" → 点商品卡 → 19.9 下单
```
**捆绑点**：Skill 输出的是**判断逻辑**（可免费给），产品卖的是**填好的 131 行数据 + 每周更新**。用户跑完 Skill 会立刻意识到：逻辑我懂了，但**数据我得一家家去查**——这正是 19.9 解决的。

### 1.5 留存与复购钩子
- **数据会过期**：截止日每周变 → Skill 输出"剩余 X 天"天然要求回来看；同一套逻辑春招再跑一遍
- **进度感**：Skill 让用户输入"已投过的企业"→ 下次来可以对比进度（"你上次投了 3 家，还剩 8 家快关的"）
- **版本钩子**：秋招版 → 补录版 → 春招版，同一 Skill 不同数据包

### 1.6 落地要点
- **Skill 名称**：`秋招投递优先级排程器`
- **一句话简介**：`填 6 项信息，告诉你今天该先投哪 3 家、哪家可以直接放弃`
- **笔记挂载引导话术**：
  > 这篇底下挂了个小工具，填一下你的专业和城市，它会按"还剩几天×你能不能投"给你排出今天的投递顺序。数据我整理在店铺里了，不想自己查的可以直接拿。
- 🔴 **处罚期纪律**：10/19 前挂载 Skill 的笔记**同样不挂商品卡、不提店铺价格**，Skill 只做种草；解禁后再接 SKU。

## 二 · 方案 2：往届生可投判定器（C 层人群专供）

**适配逻辑**：往届生是我方差异化人群（C 层笔记方向），且**痛点极硬**——"我到底还能不能投"是个有唯一答案、且答案会随时间变的问题，紧迫感天然拉满。

### 2.1 适用赛道与产品
- 绑定产品：A 店 **¥29.9「往届生专版」**（DB59 已有 20 家素材）
- 适配逻辑：往届生最怕的不是找不到信息，是**找到后不确定"我这种算不算"**。Skill 专门回答这个判定问题。

### 2.2 目标人群与核心痛点
- **人群**：24/25 届已毕业、二战考研失败后转秋招、辞职再找、已交社保怕被卡的往届生
- **场景**：看到某企业"接受往届生"，但**不敢确定自己这种（交过社保/毕业 1 年/非全日制）算不算**，投了怕白投，不投怕错过
- **未被满足的需求**：企业官方口径模糊（"毕业两年内"到底含不含？"未落实工作单位"怎么证明？）**没人给确定性答案**

### 2.3 Skill 核心能力
| 输入 | 输出 |
|---|---|
| 毕业年份 / 是否已交社保 / 学历层次 / 档案户口状态 / 目标行业 | ①**你能投的档位判定**（明确三档：稳投 / 可试但要备注说明 / 基本没戏，各给理由）②**三个高频卡点自查**（社保记录、档案去向、毕业证时间）③**一个真相提醒**：如"你说交过社保，那 X 类（央企/选调/部分银行）基本走不通，别在上面耗；Y 类（外企/民企/部分股份制银行）不看这个" |

**决策问题**：我到底该把时间花在哪一档企业上。

### 2.4 捆绑方式
判定结论里**点出企业类型但不点名具体企业**（"X 类央企"），具体哪几家、各自口径、截止日 → 指向往届生专版 29.9。
**转化路径**：被判定结果扎到（"原来我交过社保已经卡掉一半"）→ 想知道"那具体哪几家还行" → 商品。

### 2.5 留存复购
- 判定结论**随时间和政策变**（秋招→补录→春招口径不同）→ 需要复看
- 用户会带朋友来查（往届生群体互相通气，传播性强）

### 2.6 落地要点
- **名称**：`往届生可投判定器`
- **简介**：`输入毕业年份和社保状态，告诉你哪些企业类型还能投、哪些别浪费时间`
- **引导话术**：
  > 往届生的宝子，底下这个工具填 3 项就能判出来你属于哪一档。我整理了还在招往届生的那批企业，在主页店铺。

## 三 · 方案 3：网申卡点诊断器（B 层互动引擎）

**适配逻辑**：不做"模拟面试"（已有竞品占位），改做**"你被卡在哪一步"**——这是个诊断型结论，天然留缺口、天然引评论（B 层要的就是评论率）。

### 3.1 适用赛道与产品
- 绑定产品：A 店 19.9（主推）+ 后续免笔试专版
- 适配逻辑：诊断出"卡在简历/笔试/网申开放时间"→ 不同卡点对应不同产品。

### 3.2 目标人群与痛点
- 投了很多没回音，**不知道问题出在哪**——是简历被筛、笔试没过、还是压根投晚了
- 现有内容都在教"怎么写简历"，**没人帮他定位自己卡在哪**

### 3.3 Skill 核心能力
| 输入 | 输出 |
|---|---|
| 投递数量 / 收到笔面数量 / 投的时间点（开放第几天）/ 学历院校 / 岗位类型 | ①**卡点定位**（四类：投太晚 / 简历过不了机筛 / 笔试卡 / 岗位本身不匹配，给出判断依据的比值）②**下一动作建议**（一条，具体可执行的）③**留一个问题**："你的比值在 X 区间，但这个区间有两种可能，取决于你投的那批是不是……" |

**决策问题**：我下一步该改简历、还是该换投递策略、还是该投更多家。

### 3.4 捆绑方式
- 卡点 = "投太晚" → 指向**截止时间表**（19.9：别再错过）
- 卡点 = "笔试卡" → 指向**免笔试专版**（后续 SKU）
- 卡点 = "简历筛" → 指向方法论内容（免费内容养粉）

### 3.5 留存复购
- 比值会变（投得越多数据越准）→ 用户投完一批回来复测
- 天然评论区话题："我 X 投 Y 面，是什么水平？"

### 3.6 落地要点
- **名称**：`网申卡点诊断器`
- **简介**：`填 4 个数字，定位你是投晚了、简历被筛、还是笔试卡住`
- **引导话术**：
  > 投了没回音的，底下工具填四个数就能定位卡在哪一步。评论区说说你的数，我看看是不是同一批人。

## 四 · 方案 4：考公选岗匹配器（B 店专用）

**适配逻辑**：B 店「小Z整理考公选岗资料」——选岗是考公里**最典型的个性化决策 + 最强紧迫感**（报名窗口只有几天，选错等于白考一年）。

### 4.1 适用赛道与产品
- 产品：B 店选岗资料（待你补充具体价位）
- 适配逻辑：选岗 = 条件匹配（专业/学历/户籍/应届身份/基层经历），本质是**规则查询**，Skill 特别适合做规则判断。

### 4.2 目标人群与痛点
- 第一次考、不知道自己专业能报哪些岗；怕"三不限"竞争太大、又怕限得太死报不上
- **痛点**：岗位表几千行，筛选条件交叉（专业目录 vs 职位专业要求对不上是经典坑）

### 4.3 Skill 核心能力
| 输入 | 输出 |
|---|---|
| 专业名称（含专业目录大类）/ 学历 / 户籍 / 是否应届 / 政治面貌 / 是否有基层经历 / 目标地区 | ①**你能报的岗位类型分级**（稳妥档 / 可冲档 / 热门三不限，各说明竞争度来源）②**三个易踩坑检查**（专业目录是否对得上、备注栏隐藏条件、"应届"身份怎么认定）③**一个提醒**：如"你的专业在目录里属于 XX 类，职位表里写 YY 的你能报，写 ZZ 的报不了——这一条每年都有人搞错" |

**决策问题**：我该报限制多的冷门岗，还是竞争大的三不限。

### 4.4 捆绑方式
Skill 讲**判断规则**，产品卖**按地区/专业筛好的岗位表 + 备注栏隐藏条件整理**。
- 紧迫感来源：报名窗口倒计时（Skill 输出里带"距离报名截止 X 天"）

### 4.5 留存复购
- 国考 → 省考 → 事业编 → 春招补录，一年多次窗口，每次都要重跑
- 用户会带回同专业同学

### 4.6 落地要点
- **名称**：`考公选岗匹配器`
- **简介**：`填专业和身份，告诉你哪些岗位类型能报、哪些备注栏条件会卡你`
- **引导话术**：
  > 不确定自己专业能报什么岗的，底下填一下就出结果。完整岗位表和备注栏隐藏条件我整理好了。

## 五 · 方案 5（跨品类示范）：护肤成分冲突排查器

> 这一类目你没给，**给它是为了演示这套结构怎么迁移**——换成美妆/母婴/家居/健身，逻辑完全一致。

### 5.1 适用赛道与产品
- 赛道：护肤 / 成分党
- 绑定产品：店铺在售的具体精华/面霜（**这里必须落到具体 SKU，才谈得上"深度捆绑"**）
- 适配逻辑：成分冲突是**有标准答案的知识判断**，Skill 能做；但"你的皮肤该用哪个浓度、怎么排顺序、多久见效"需要产品承接。

### 5.2 目标人群与痛点
- 手里有 5-8 个产品，不知道能不能叠、顺序对不对、为什么用了还烂脸
- 未被满足：**没人针对"我现有的这一堆"给结论**，通用科普解决不了

### 5.3 Skill 核心能力
| 输入 | 输出 |
|---|---|
| 现有产品成分表（可粘贴）/ 肤质 / 主要诉求（美白/抗老/祛痘）/ 是否敏感 | ①**冲突清单**（明确哪两个不能同用，为什么）②**使用顺序与时间间隔**③**一个预算/用量测算**：按你给的诉求，一个周期要多少量、大概多少钱 ④**留口**："你这个组合里缺一个 XX 步骤，具体产品要看你的耐受度" |

### 5.4 捆绑方式
输出里的"缺的步骤/需要补的成分"→ 直接对应店铺在售的那一支产品；用量测算 → 一次买几支够一个周期（**自然带出客单量**）。

### 5.5 留存复购
- 空瓶了要复购（用量测算已预告时间）
- 换季肤质变化 → 重跑

### 5.6 落地要点
- **名称**：`护肤成分冲突排查器`
- **简介**：`粘贴你的产品成分表，告诉你哪两个不能叠、怎么用、一个周期要多少钱`
- **引导话术**：
  > 不知道手头这几支能不能一起用的，把成分表贴给底下这个工具。缺的那一步我用的是 XXX。
