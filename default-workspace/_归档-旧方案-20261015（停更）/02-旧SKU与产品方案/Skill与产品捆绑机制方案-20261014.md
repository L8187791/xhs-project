# Skill × 产品 捆绑机制方案（2026-10-14）

> **回答**：怎么让 Skill 搭配我们的产品？怎么让用户"用这个 Skill 操作我们的产品"？
> **范围**：方案 ①（投递优先级排程器）+ 方案 ⑤（冷门机会雷达）。
> **状态**：**只定方案，不做工程**（L 16:3x 指示）。下文提到的 CSV / SKILL.md 骨架仅为验证可行性所留的最小样张，**未展开交付**。

## 〇 · 先说一个必须先认的机制真相

**Skill 运行在用户自己的 Agent 里（Claude Code / OpenClaw 等），我们控制不了它跑起来之后的行为。**
而且 RED Skill 平台规范明确要求：**代码逻辑必须透明、不得含隐藏行为或后门**。

这两条合起来否定了一个常见想法——**在 Skill 输出里插广告、插购买链接**：
- 技术上我们改不了用户本地那份（上传后是分发，不是托管运行）
- 规则上不允许（隐藏行为会被下架，还可能限制发布权限）

**所以捆绑必须做在「输入侧」，不能做在「输出侧」。**

一句话答案：

> **产品不是 Skill 的广告位，产品是 Skill 的燃料。**
> Skill = 引擎（免费，谁都能装）｜我们的表格 = 数据文件（付费，喂给这个引擎）
> 用户买了表 → 把文件放进目录 → Skill 自动读全量 131 家 → 跑出完整排程。

这就是"让用户用 Skill 操作我们的产品"的真实形态：**他操作的不是我们的产品界面，是把我们的数据喂进一个他已经会用的工具**。

## 一 · 三级输入设计（捆绑的技术核心）

Skill 启动时自动按序找数据，**取第一个找到的**：

| 档 | 触发条件 | 覆盖 | 用户体验 | 我们的位置 |
|---|---|---|---|---|
| **L0 示例** | 什么都没有 | **12 家**（内置） | 能跑出真结果，建立"这工具懂我" | 输出末尾必须声明"本次仅基于 12 家示例，约占完整库 9%" |
| **L1 粘贴** | 用户手打/粘贴清单 | 粘贴的这些 | 能用，但**数据要自己一家家找** | 让用户亲身体会"找数据"有多累 |
| **L2 文件** 🔴 | 目录里有 `timetable*.csv` | **全量 131 家** | 一次跑完，直接出完整排程 | ← **产品在这里进场** |

### 为什么这个设计能转化

**L0 负责建立信任**（免费给真结果）→ **L0 末尾暴露 9% 覆盖率**（不是硬广，是功能必须声明的边界）→ **用户想跑全量，只有两条路**：
- 走 L1：自己一家家查 131 家（保守 5–10 小时）
- 走 L2：**拿到现成的 CSV 文件**（19.9）

**我们把"买不买"变成了"你愿意花十小时还是十九块九"**——这不是话术，是真实的时间成本对比。

### 关键工程约束（只需记住一条）

**我们交付的 CSV 字段，必须和 Skill 内置示例库的字段完全一致**，这样文件一放进去就能无缝替换，不需要任何转换：

```
企业名称, 截止日期, 企业性质, 招聘方向, 工作地点, 学历, 来源可信度, 投递入口
```

> 最小样张已生成验证：`_协作/redskill/01-秋招投递优先级排程器/data/sample12.csv`（12 家）
> 与 `_协作/redskill/timetable_full_131.csv`（131 家）——**两者字段逐字一致，可直接互换**（已实跑验证可解析）。

## 二 · 用户操作路径（从刷到笔记到用上产品）

```
① 刷到笔记（标题带紧迫/信息差）
        ↓
② 点笔记末尾 Skill 组件 → 详情页看到「你会得到什么」+ 使用人数
        ↓
③ 复制口令 → 粘贴进自己的 AI 工具 → 装上（10 秒）
        ↓
④ 填 6 项 → 跑出 12 家排程（🔴 真结果，含"建议跳过"）
        ↓   ← 信任在这一步建立
⑤ 看到"本次仅基于 12 家示例（约 9%）"
        ↓   ← 缺口在这一步产生
⑥ 想要全量 → 两个选择：自己查（5-10 小时）/ 拿现成 CSV（19.9）
        ↓
⑦ 拿到 CSV → 放进同目录 → 再跑一次 → 131 家完整排程
```

**第 ⑦ 步是复购钩子的起点**：截止日每周变，他下周想再跑一次准的 → 需要新版 CSV → 回来拿。

## 三 · 🔴 但你必须知道：多数人不会走完这条路径

用户要装 Claude Code / OpenClaw 才能跑 Skill。**秋招大学生里装这些的是少数**。

所以真实转化结构是这样的：

| 人群 | 占比（推断） | 他们怎么被转化 |
|---|---|---|
| **A. 不装 Agent，只看到笔记** | **大部分** | 靠**笔记正文 + 商品卡**转化。Skill 组件对他们只起**专业背书**作用（"这人还做了工具"） |
| B. 装了，跑 L0 就走 | 一部分 | 拿到 12 家结果就满足 → 靠**输出末尾那句"仅覆盖 9%"**制造不完整感 |
| C. 装了，要跑全量 | 少数但**意图最强** | 这就是最精准的购买人群 —— 他已经投入时间装工具、填信息，**沉没成本越高越想补全** |

**结论**：**Skill 是放大器，不是收银台**。别指望它直接收单，它的价值是：
1. 官方流量扶持（S 级）
2. 使用人数 = 社会认同
3. 让笔记显得更专业
4. 筛出 C 类高意图用户

**真正收单的仍然是笔记正文 + 商品卡。**

### 针对 A 类人群（多数）的配套动作

在笔记正文里放**"全量跑完的效果"**——即用 131 家跑出来的排程结果截图（不是 12 家的）。
让用户**看见**"131 家排出来长什么样"，他不需要装任何东西也能感知价值。

## 五 · 两个方案各自的捆绑点（① 排序 / ⑤ 发现）

| | ① 投递优先级排程器 | ⑤ 冷门机会雷达 |
|---|---|---|
| **引擎（免费）** | 优先级算法 + 取舍逻辑 | 冷门度分类逻辑 + 竞争度判断 |
| **示例库（12 家）** | 近期截止的 12 家（制造紧迫） | 冷门机会 12 家（地方城商行/券商分支/地方国企/持牌） |
| **燃料（付费）** | 131 家全量 + **学历门槛/投递入口**字段 | 131 家全量 + **"招满即止"标注** |
| **独有付费理由** | 示例库里没有"学历门槛"，判断不了"我这条件能不能投" | 示例库里没有"招满即止"，**这类机会没有任何倒计时提醒** |
| **留缺口的方式** | 声明覆盖 9% | 声明覆盖 9% + "招满即止类只能靠全量数据盯" |

**⑤ 的杀手锏**：`招满即止` 这个字段——示例库给 1–2 家，全量才有完整标注。而招满即止 = **没有提醒、等你知道就没了**，这是它最值钱的地方。

## 六 · 合规边界（必须守住）

| 项 | 规定 |
|---|---|
| Skill 内部 | 🔴 **不提价格、不提店铺、不引导私信、不插链接**。用户问"完整数据从哪来"→ 只说"需要一份字段一致的 CSV"，**不做任何商品引导** |
| 处罚期（至 10/19） | 挂载 Skill 的笔记同样**不挂商品卡**；Skill 只种草 |
| 平台规范 | 功能描述真实、代码透明、不超范围索权 —— 我们的"读取本地 CSV"是明示功能，**完全合规** |
| 数据诚实 | 来源可信度 C 的企业（表内 50 家）输出时加"以企业公告为准" |
| 不编造 | 任何企业名/日期必须来自数据文件，读不到就说"我这版数据里没有" |

## 七 · ✅ 支持 vs ❌ 反对

### ✅ 支持
| 论点 | 依据 | 等级 |
|---|---|---|
| 捆绑在输入侧 → 不受"输出不可控"影响 | RED Skill 跑在用户 Agent 内 | **S** |
| 明示功能不违规 | 平台规范只禁"隐藏行为/后门"，读本地 CSV 是明示功能 | **S** |
| 示例库与全量可无缝替换 | 字段逐字一致，已实跑验证可解析 | A（本地验证） |
| 示例 12 家是真数据，跑得出真结果 | 取自 timetable.json 131 家 | A |
| 门槛四项已达标 | 粉丝 1097 / 注册≥180天 / 已实名 | **S** |

### ❌ 反对 / 风险
| 论点 | 依据 | 等级 |
|---|---|---|
| 🔴 **多数用户装不了 Agent** | 需 OpenClaw/Claude Code，大学生比例低 | **S** + C |
| 🔴 **买了不会用** | "把 CSV 放进目录"对普通用户有认知门槛 | C（推断）→ 需用傻瓜指引对冲 |
| 用户可走 L1 自己填数据 | 理论上能绕过付费，但成本 5–10 小时 | C |
| Skill 无法直接收单 | 转化仍在笔记正文 | C |
| 处罚期可能卡开通 | 门槛含"无违规" | **S** + A |

### 我的倾向（推断）
**机制成立，值得做。** 三个理由：
1. 这是**唯一合规且可控**的捆绑方式（输入侧）
2. 即使 90% 用户不装 Agent，剩下 10% 是**意图最强的精准人群**（已投入时间装工具、填信息）
3. 产品侧改造极轻（只是多给一个 CSV 文件），**边际成本几乎为零**

**但顺序要对**：先把 19.9 的转化跑通（这是主矛盾），Skill 作为放大器同步推进，不要本末倒置。
