## 一 · 机会评估（创业验证框架）

### 1.1 一句话定义

> **For** 2027 届应届生与近届往届生，**who** 秋招信息散落在几十个渠道、自己一家家查官网必然漏投，
> **「求职时间表研究所」提供** 一份逐条标注「来源等级 + 核验日期 + 硬截止日」的可筛选企业时间表（后续叠加投递排程工具），
> **不像** 小红书零散笔记与搬运表那样过期、无出处、无法排序。

### 1.2 问题评估矩阵

| 维度 | 判定 | 依据 |
|---|---|---|
| **Frequency** | **High** | 秋招 9–11 月截止节点每周密集发生；表内 41/84 家在 10 月底前截止（WB140） |
| **Severity** | **High** | 漏一家 = 少一次机会，且往届生窗口更窄、不可逆 |

### 3.2 赛道边界（**不做**）

- ✅ **做**：秋招网申投递（截止 / 节奏 / 填表 / 核验 / 投了没回音 / 工具）

### 3.3 付费决策链与卡点

```
推荐池 → 封面(CTR 20.02% ✅) → 观看 → 互动(10.45% ✅) → 收藏(4.39% ✅)
```

### 6.2 文案风格

| 项 | 规范 |
|---|---|
| 口吻 | 第一人称、口语、家常（「我一家家翻过来的」）；**禁机械对偶、禁 AI 腔** |

| 结尾 | 🔴 **必须是问题**（禁总结陈词、禁预告「我会另发一篇」） |

### 6.3 🔴「不说全」纪律（**我们卖的就是信息差，这是核心思路不是技巧**）

| 层 | 留白方式 |
|---|---|
| A 层时效稿 | 今天截止 5–6 家 → **只说 2–3 家最急的**，其余写「整理在表里」 |
| B 层机会稿 | **列 3 个，留 2 个不说** + 结尾抛问题 |
| C 层往届生稿 | **说 3 家不说全部** + 带 1 家反例 |
| 图片 | **不给全量数据**（封面只给核验样例 + 部分真实数据） |
| 禁 | 完全不说（要「说一半留一半」） |

> **A 级实证**：「3 类没人知道的高薪公司双非大专也能进」**3 万赞 / 1 万评论**——**说数量不说名字 = 评论率发动机**。
> **反例**：给结论型 4496 赞 / **仅 6 评**。

### 6.4 文案禁用（P0/P1 摘要，完整见 §十）

- ❌ 「完整版在左下角 / 主页 / 组合包里」——**诱饵引流结构（永久禁令）**
- ❌ 「六险一金 / 十几薪 / 日薪 150–200 / 年薪 X 万」——待遇**只能模糊写「福利不错」**
- ❌ 「二本能进 / 双非可投 / 不限院校」——门槛**不写，或只写「对学校卡得没那么死」**
- ❌ 绝对化用语（最 / 第一 / 唯一 / 100% / 全网 / 保证）→ P1，伤推荐
- ❌ 煽动紧迫（秋招人注意 / 最后一天 / 再不投）→ 除「核验时间 + 具体日期」同时出现的时效豁免
